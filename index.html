Computer vision · Deep learning · Feb – Apr 2026

Deepfake ForensicsFrequency-aware SE-ADDNet

Problem
Faces can now be faked by inpainting, identity swaps or text-to-image models. A detector has to catch all of them — and a bare REAL/FAKE label gives a reviewer nothing to check.
Solution
A dual-stream network. A spatial stream (EfficientNet-B5 with SE channel attention and ADD spatial attention) reads manipulation cues in pixels; a frequency stream runs the image’s FFT magnitude spectrum through a small CNN. A learnable, sigmoid-gated FrequencyGate fuses the two before classification, and Grad-CAM shows which regions drove the call.
What I built
The full pipeline: model, focal loss (γ = 2) with weighted sampling for the roughly 3:1 fake-to-real imbalance, FP16 mixed-precision training with cosine schedule and early stopping on validation AUC, evaluation scripts, CLI inference that emits a JSON report, and a Streamlit app serving Grad-CAM localisation.
Decisions
Focal loss and weighted sampling instead of plain cross-entropy, because fakes outnumber reals about 3:1. Early stopping on validation AUC rather than loss: the run keeps the epoch-13 checkpoint (of 23), after validation loss had flattened while training loss kept falling.
Reading the results
The test split is 9,000 fakes and 3,000 reals, so a model that says “fake” every time would already score 75% accuracy. That is why specificity (94.2%), EER (5.46%) and AUC are shown beside accuracy. The model misses 473 of 9,000 fakes and flags 175 of 3,000 real faces.
Limits
Results come from one benchmark (DeepFakeFace, an ~80/10/10 split of ~120K images). No cross-dataset evaluation is reported, so read the numbers as in-distribution. Validation accuracy plateaus around 93–95% while training accuracy keeps climbing, a mild overfit.

Technical details
Dataset
OpenRL/DeepFakeFace, ~120K images: real faces from the “wiki” subset, fakes from inpainting, InsightFace swaps and a text-to-image generator. 80/10/10 split, seed 42.
Input
256 × 256 face crops. The frequency stream takes the FFT magnitude spectrum of the same image.
Training
AdamW, lr 1e-4, weight decay 0.05; cosine schedule with 3 warm-up epochs; batch size 16; FP16 mixed precision; focal loss γ = 2; early-stopping patience 10. 23 epochs were run.
Test metrics
12,000 images. Accuracy 94.6% · F1 96.34% · AUC 98.95% · precision 97.99% · recall 94.74% · specificity 94.17% · EER 5.46% · average precision 99.65%.
Serving
CLI inference that writes a JSON report; Streamlit app that overlays Grad-CAM on the face.

MLOps · Applied AI · Jan – Feb 2026

Crop Disease AdvisorVision + LLM pipeline

Problem
A farmer photographing a sick leaf needs more than a class label. They need a plan — what to treat it with, how much yield is at risk, and what suits their region and season.
Solution
Two stages. An EfficientNet-B4 classifier identifies the disease across 38 classes (14 crops, PlantVillage). Its output feeds a Qwen2.5-3B model, QLoRA-tuned to return a structured JSON plan with organic and chemical options, yield impact and region-season advice. If the JSON fails to parse, the advisor retries at a lower temperature, then falls back to a curated lookup table.
What I built
Both models, the instruction dataset (diseases × regions × seasons × farmer profiles), a FastAPI service with a Vite front end and multi-stage Docker build, W&B experiment tracking, model releases on the Hugging Face Hub, a pytest suite covering the API, model forward pass and output schema, and deployments on Render and Hugging Face Spaces.
Decisions
The language model’s output is never trusted raw: it must parse into a fixed JSON schema, otherwise the request retries at a lower temperature and finally falls back to a curated lookup table. The result is a response that is always well-formed. CI runs black, flake8 and CPU tests; the deploy workflow tests first and only then pushes to the Hugging Face Space.
Limits
The LLM stage needs a GPU, so the CPU deployment serves the lookup fallback. Coverage is 38 classes, and the advice is model-generated decision support, not agronomic guidance. The tests use mocked weights, so they check structure rather than accuracy.

Pipeline

  1. inLeaf photo, 224 × 224
  2. seeEfficientNet-B4 → disease + confidence

Technical details
Classifier
EfficientNet-B4, 38 classes across 14 crops (PlantVillage), 224 × 224 input. Reported: accuracy 96.8%, macro-F1 95.4%, AUC 97.1%.
Language model
Qwen2.5-3B, QLoRA with rank 16 on a 4-bit NF4 base. Reported: BERTScore F1 81.68%, perplexity 1.42, 100% JSON/schema validity.
Service
FastAPI with /predict, /health and /classes; Vite front end; multi-stage Docker build.
Two modes
Phase 1 serves the curated lookup advice. Phase 2 adds the LLM advisor when a GPU is available.
Tests
pytest on the API, the model forward pass and the output schema, using mocked weights: they check structure, not accuracy.

03

LLM fine-tuning · QLoRA · Serverless GPU

Sherlock Persona ModelPersona-Modeling

Problem
A general-purpose chat model answers in a general-purpose voice. I wanted one that consistently reasons and speaks like Sherlock Holmes — deductive, Victorian — without paying for a full fine-tune.
Solution
QLoRA on Qwen2.5-7B-Instruct. The base model is loaded in 4-bit NF4 (about 14 GB down to 5 GB, per the README) with frozen weights, and LoRA adapters (r = 64, α = 16, on q_proj and v_proj) are trained with TRL’s SFTTrainer on chat-formatted Holmes dialogue.
What I built
The whole lifecycle: a data-preparation step that turns the corpus into chat-format JSONL, training, a base-versus-fine-tuned evaluation suite, loss and metric plots, a Modal backend on a serverless A100 that scales to zero, and a Streamlit chat UI with a dark detective theme.
Decisions
QLoRA rather than a full fine-tune: the 7B base sits frozen in 4-bit while only small adapters on the attention query and value projections are trained. Serving on Modal means the A100 scales to zero when nobody is chatting, at the cost of a cold start on the first message.
Reading the results
Perplexity falls from 45.31 to 7.52 on held-out Holmes dialogue. Cosine similarity to reference replies rises from 0.096 to 0.259, a clear gain over the base model that is still low in absolute terms.
Limits
Evaluation is perplexity and sentence-embedding similarity on held-out Holmes dialogue. Both measure style fit; neither is a human or task-based judgement of the persona.

Base → fine-tuned

  • 45.31→7.52Perplexity · ~6× lower
  • 0.096→0.259Cosine similarity

Pipeline

  1. dataCorpus → chat-format JSONL
  2. quantQwen2.5-7B · 4-bit NF4
  3. tuneLoRA r = 64 · SFTTrainer
  4. evalPerplexity + cosine similarity
  5. serveModal A100 → Streamlit chat

04

Deep learning · Amazon ML project · Oct 2025

Multimodal Price EstimatorCoCa + SigLIP ensemble

Problem
Predict a product’s price from its multimodal content, with an error measure (sMAPE) that treats cheap and expensive items fairly — and fast enough to be usable at inference time.
Solution
An ensemble of parallel MLPs trained on CoCa and SigLIP multimodal embeddings, designed for low-latency inference.
Decisions
Small MLP heads on frozen pretrained embeddings instead of fine-tuning a large multimodal model: faster to train and cheap to run, which is how it reaches 0.12 s per sample.
Limits
A 40% sMAPE is a large typical error, so this is a working baseline rather than a pricing model I would deploy. The two figures here are the ones the repository reports.
